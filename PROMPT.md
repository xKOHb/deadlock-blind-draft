# Промт для следующей ИИ / нового чата: проект «Deadlock Minigames»

Ты продолжаешь работу над сайтом. Весь сайт лежит в одном файле `index.html` (React 18 UMD + htm, Tailwind CDN, Firebase Realtime Database 8.10.1). Рядом лежат `favicon.svg` и `og.png`. Общайся с автором по-русски, коротко и без воды.

## АУДИТОРИЯ (важно)
Сайт для друзей и друзей друзей (человек 10-20), не для случайной публики. Не усложняй защиту от злоупотреблений, тон дружеский, без лишней бюрократии.

## ПРАВИЛА РАБОТЫ (обязательно)
1. Прежде чем править, прочитай присланный `index.html` целиком. Не переписывай сайт с нуля, делай точечные правки.
2. После КАЖДОЙ порции правок отдавай автору обновлённые файлы и обновлённый `PROMPT.md`. В нём должен быть актуальный список «Что уже сделано» (этот же текст с этими же правилами сохраняй в файле всегда).
3. Не добавляй на сайт значок шифа (маленькая иконка персонажа Shiv/«заточка» в углу иконок предметов из игры). Его на сайте быть не должно.
4. Не выдумывай данные предметов. Если не уверен, скажи об этом автору.
5. Автор не программист: объясняй простыми словами, что поменялось и что нужно сделать руками (например, заменить `YOUR-DOMAIN`).

## О проекте
- Главная страница = хаб выбора мини-игры (`Hub`). Адрес `#draft` открывает «Слепой драфт», пустой hash открывает хаб. Заголовок сайта нажимается и ведёт в хаб.
- Мини-режимов сейчас ДВА: «Слепой драфт» (`#draft`) и «Чёрный аукцион» (`#auction`, рабочее название, автор может переименовать). Режимы добавляются в массив `games` внутри `Hub`, а адреса в `gameFromHash` и `GAME_NAME`. «Сборки героев» (`#builds`) НЕ мини-режим: на хабе это отдельный раздел «Справочник» под карточками режимов (`buildsArt`), не добавлять сборки в `games`. Сайт это режимы ДЛЯ ИГРЫ в Deadlock (не «по мотивам»).
- «Слепой драфт» (Deadlock): игроки по очереди загадывают друг другу по 3 карты предметов, выбирают одну вслепую. Режимы: «Баланс» (тир раунда общий) и «Хаос» (тир выбирает сам игрок). Онлайн через Firebase (`games/{CODE}`) или локально на одном экране. Сайт ЛИШЬ помощник: настоящий бой 1 на 1 идёт в игре, поэтому сайт НЕ объявляет победителя и не пишет «ничья».
- Каталог предметов грузится из Deadlock Assets API (`api.deadlock-api.com/v1/assets/items`, на английском и русском), кэш в localStorage (`bd_catalog`, версия v:2).

Потом роли меняются. Бюджет и число предметов настраиваются. Правила в одной функции `auReduce`, она работает и локально, и онлайн (транзакции Firebase, путь `auctions/{CODE}/state`). Победитель не объявляется.
- ВАЖНО: в правилах Firebase Realtime Database должен быть разрешён путь `auctions` (так же, как `games`), иначе онлайн-аукцион не заработает (локальный режим работает всегда).

- Исправлено: подсказка при наведении гаснет при клике; кнопка «i» на карточках убрана; кнопки +1/+5/+10 в аукционе прибавляют к числу в поле; блок выбора предметов шире (1180px); кнопки выбора тира в «Хаосе» перерисованы.
- Конфликты сборок в ДРАФТЕ решаются заменой (вместо блокировки). В игре улучшение съедает компоненты, поэтому: если выбранный предмет конфликтует с инвентарём (`conflictsFor`: компонент уже имеющегося улучшения, второе улучшение того же предмета, лимит 4 активных), лишний предмет пропадает и заменяется предметом того же тира и типа (активный/пассивный) без новых конфликтов (`eligibleRepl`). Порядок раунда: загадывание, выбор (в любом порядке), при конфликте фаза `vote` (оба голосуют: R случайно, O выбирает потерявший, X выбирает соперник; при разных голосах рулетка 50/50 между двумя выбранными), при O/X фаза `choose` (выбор замены из подходящих), затем `recap`. Всё считается чисто в `derive` из ходов (`vote`, `repl` в `moves[seat][round]`), случайность детерминирована через `settings.seed` (мета комнаты `seed`) и `hash32`, поэтому у обоих игроков одинаковый результат. Один голос на раунд покрывает все споры раунда. UI: `DisputePanel`. Исключений нет.
- В АУКЦИОНЕ те же замены, что в драфте (ничего больше не блокируется, кроме уже проданных предметов, `auUsed`). Если выигранный предмет конфликтует с купленным (`conflictsFor`), фаза `dispute`: оба голосуют (R/O/X, рулетка при разных голосах, `hash32` от `st.seed`), потом при O/X выбирают замену из `eligibleRepl(..., used)` (того же тира и типа, которого ещё не было в торгах). Всё считает чистая функция `auPlan(st)`, правила в `auReduce` (действия `vote`, `choose`, состояние `st.dp`, итог `st.rep`, `from` в `log` и `won` у замен). UI: `AuDispute`, `AuRepl`. Таймер в споре не идёт.
- Аукцион: реванш (действие `rematch`, первым ходит другой игрок), ссылка-приглашение `#auction-КОД` (`gameFromHash`, `hashRoom`), таймер на ставку (`cfg.timer`, `deadline`, действие `timeout`, по истечении автоматический «Пас»).
- Звуки (`Sfx`, WebAudio, настройка `sfx`): удар молотка при продаже, звон при ставке, щелчок по карточкам. Цвет оформления: палитры в `ACCENTS` (настройка `accent`). Полной светлой темы нет.

- Выбор карт в драфте больше не по очереди: фаза `pick` (оба игрока выбирают одновременно или в любом порядке, `derive`).
- Аукцион: подтверждение перед выставлением предмета (выбор, потом кнопка «Выставить») и двойной клик для «Пас» («Точно пас?»). Автопас по таймеру без подтверждения.
- Темы оформления (`THEMES`, `html[data-theme=...]` в CSS): Золотой нуар, Сапфировое пламя, Багровый, Нефрит, Спиритизм. Цвета панелей, рамок и кнопок идут через CSS-переменные (`--acc`, `--btn1..4` и др.); новые цвета в CSS писать через них.

## Мини-игра «Угадай предмет» (сделано)
- Хэш `#guess` / `#guess-КОД`. Компоненты `Guess` (лобби и подключение), `GuessBoard` (игровое поле); логика: `guMake` (вопросы), `guInit`, `guReduce` (чистая функция правил). Путь в Firebase: `guess/{КОД}/state` (константа `GU_PATH`).
- Правила: 4 варианта ответа, подсказка либо силуэт иконки, либо список характеристик. Верный ответ +1, кто ответил верно первым (порядок `n` задают транзакции Firebase) получает ещё +1. Режим «одному» без бонуса. Нет таймера.
- ВАЖНО: в правилах Firebase Realtime Database нужно разрешить узел `guess` так же, как `auctions` (чтение и запись для `guess/$code`). Без этого онлайн не заработает, будет ошибка доступа; режим «одному» работает и без базы.

Правила: обоим игрокам даётся одинаковый бюджет душ (настройка 3000..30000), каждый собирает билд из предметов, не превышая бюджет, а потом оба показывают билды одновременно. Фазы: `lobby`, `build` (каждый выбирает предметы, чужой выбор скрыт, кнопка «Готов»), `reveal` (показать оба билда и сумму), `vote` (оба голосуют, чей билд лучше, за себя голосовать нельзя; при ничьей побеждает тот, кто потратил меньше). ## ПРОМТ на будущее: «Челлендж-карточки» (онлайн на двоих)
Добавь мини-игру «Челлендж-карточки»: хэш `#cards` и `#cards-КОД`, путь Firebase `cards/{КОД}/state`. Идея: перед матчем в Deadlock игроки тянут случайные условия на матч (например «без активных предметов», «только оружейные предметы», «первый предмет не дороже 800», «нельзя покупать предметы тира IV»). Правила: колода из ~25 условий хранится в коде отдельным массивом (id, текст ru/en, редкость). Каждый игрок по очереди вытягивает карточку для соперника, у каждого есть один «реролл» и одна «защита» (карточку можно отклонить). Фазы: `lobby`, `draw` (ход игрока), `review` (соперник принимает, рероллит или защищается), `done` (итоговый список условий для обоих, кнопка «Скопировать итог»). Логика в чистой функции `caReduce`, карточки выбирает хост через `seed` (как `guMake`), чтобы у обоих игроков порядок колоды совпадал. Нужны режим «на одном экране» и онлайн. Дальше те же требования: точечные правки, проверка `node --check`, тест логики на Node, обновление PROMPT.md.
